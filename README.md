# FK407 STM32CubeMX CMake Template

This repository is a reusable STM32F407VETx firmware template generated by STM32CubeMX with the CMake toolchain. It includes a minimal USART1 `Hello World` bring-up test, DAPLink/pyOCD flash support, and workspace-local VS Code tasks.

The template is intentionally not tied to one PC. User-specific values such as tool paths, pyOCD target name, and serial port are collected in `template.config.json`.

## Project Facts

- MCU: STM32F407VETx
- Build system: CMake presets with Ninja
- Toolchain: Arm GNU Toolchain for bare-metal `arm-none-eabi-*`
- Debug/flash probe: DAPLink / CMSIS-DAP through pyOCD
- Firmware entry: `Core/Src/main.c`
- UART test: USART1, PA9 TX, PA10 RX, 115200 8N1
- Debug output: `build/Debug/FK407-template.elf`

## Install Prerequisites

Install these tools before building:

- CMake 3.22 or newer
- Ninja
- Arm GNU Toolchain for `arm-none-eabi-gcc`, `arm-none-eabi-gdb`, `arm-none-eabi-objcopy`, and `arm-none-eabi-size`
- Python 3.x
- pyOCD: `python -m pip install -U pyocd`
- VS Code, recommended extensions:
  - `ms-vscode.cpptools`
  - `ms-vscode.cmake-tools`
  - `marus25.cortex-debug`
  - optional: `ms-vscode.vscode-serial-monitor`

Validate the base tools:

```powershell
cmake --version
ninja --version
arm-none-eabi-gcc --version
arm-none-eabi-gdb --version
python --version
pyocd --version
```

If `arm-none-eabi-gcc` resolves to an old vendor SDK copy, set `armToolchainBin` in `template.config.json` instead of relying on PATH.

## Configure This Template

Edit `template.config.json` after cloning:

```json
{
  "projectName": "FK407-template",
  "buildPreset": "Debug",
  "cmakePath": "cmake",
  "armToolchainBin": "",
  "pyocdPath": "pyocd",
  "pyocdTarget": "stm32f407vetx",
  "pyocdOptions": ["-O", "cmsis_dap.prefer_v1=true"],
  "serial": {
    "port": "COM8",
    "baudRate": 115200,
    "dataBits": 8,
    "parity": "None",
    "stopBits": "One"
  }
}
```

Important fields:

- `armToolchainBin`: leave empty if the correct Arm GNU Toolchain is already first in PATH. Set an absolute path like `C:\\Program Files\\Arm GNU Toolchain arm-none-eabi\\bin` when multiple toolchains are installed.
- `pyocdPath`: use `pyocd` from PATH or an absolute path to pyOCD.
- `pyocdTarget`: pyOCD target name. This template uses `stm32f407vetx`.
- `pyocdOptions`: keep `cmsis_dap.prefer_v1=true` for DAPLink probes that work better through CMSIS-DAP v1/HID on Windows.
- `serial.port`: set this to the local USB-UART port, for example `COM8`.

If you change `armToolchainBin` after CMake has already configured the project, delete `build/Debug` and configure again so CMake does not keep the old compiler path in its cache.

## Install The MCU Pack

Find and install the pyOCD CMSIS-Pack for the MCU:

```powershell
pyocd pack find STM32F407VETx
pyocd pack install STM32F407VETx
pyocd list --targets --name stm32f407vetx
```

The local `pyocd.yaml` keeps DAPLink/SWD options that are useful for this board family. The target itself is passed from `template.config.json`.

## Build

Recommended helper command:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/template-task.ps1 check-tools
powershell -NoProfile -ExecutionPolicy Bypass -File tools/template-task.ps1 configure
powershell -NoProfile -ExecutionPolicy Bypass -File tools/template-task.ps1 build
```

Raw CMake commands also work when PATH is already correct:

```powershell
cmake --preset Debug
cmake --build --preset Debug
```

Expected output:

```text
build/Debug/FK407-template.elf
```

## Flash With DAPLink

Connect the board through DAPLink and verify the probe:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/template-task.ps1 probe
```

Flash the current Debug ELF:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/template-task.ps1 flash
powershell -NoProfile -ExecutionPolicy Bypass -File tools/template-task.ps1 reset
```

Equivalent raw command:

```powershell
pyocd flash -O cmsis_dap.prefer_v1=true --target stm32f407vetx build\Debug\FK407-template.elf
```

## Serial Hello World Test

The firmware sends `Hello World\r\n` once per second through USART1. Update `serial.port` in `template.config.json`, then run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/template-task.ps1 serial-test
```

Expected output:

```text
Hello World
Hello World
Hello World
```

If nothing appears, check the UART TX/RX crossover, shared ground, the selected COM port, baud rate, and whether the USB-UART adapter is connected to PA9/PA10.

If the helper reports that the COM port cannot be opened, close any other serial terminal first. Common owners are VS Code Serial Monitor, vendor serial bridge tools, PuTTY, Tera Term, or another PowerShell session.

## VS Code

Open this folder in VS Code and use these tasks:

- `Check Tools`
- `Probe DAPLink`
- `Configure Debug`
- `Build Debug`
- `Flash Debug`
- `Serial Test`

The tasks call `tools/template-task.ps1`, so they use `template.config.json`.

Automatic CMake configure-on-open is disabled on purpose. Use `Configure Debug` so the helper can apply `template.config.json` before CMake selects a compiler.

The Cortex-Debug launch configuration is `Debug STM32 via DAPLink`. It reads:

- target from `.vscode/settings.json` key `fk407.pyocdTarget`
- GDB path from `.vscode/settings.json` key `fk407.gdbPath`

Set `fk407.gdbPath` to an absolute `arm-none-eabi-gdb` path if Cortex-Debug cannot find GDB from PATH.

## Firmware Customization Rules

Most CubeMX-generated files are regenerable. Put application code inside `/* USER CODE BEGIN ... */` and `/* USER CODE END ... */` blocks whenever possible.

Safe places for user code:

- `Core/Src/main.c` for bring-up logic and the main loop
- `Core/Src/<peripheral>.c` user blocks for peripheral-specific hooks
- `Core/Inc/<peripheral>.h` user blocks for declarations
- top-level `CMakeLists.txt` for extra user-owned source files

Avoid editing `cmake/stm32cubemx/CMakeLists.txt` by hand unless you intentionally accept that CubeMX may overwrite it.

## Current Verification Snapshot

On the original bring-up PC, this template was verified with:

- Arm GNU Toolchain 14.2.1
- pyOCD 0.44.0
- DAPLink CMSIS-DAP probe
- COM8 at 115200 8N1

The successful serial output was repeated `Hello World` lines. Other users do not need the same tool versions, but they should use a modern Arm GNU Toolchain and install the correct pyOCD pack for `STM32F407VETx`.
